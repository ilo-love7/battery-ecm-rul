## 二、阶段推进

### 阶段 0：数据验证（`validate_nasa.py`）

先用 NASA 的 B0005 跑通「打开 `.mat` → 取放电段 → 画 V-t 曲线」。

**目的不是出图，是确认三件事**：文件能读、字段名对得上、时间轴单调。这一步只花十几分钟，但后面所有问题都能靠它定位——比如后来发现某颗电池 `Capacity` 为空数组时，就是拿这条基线比对出来的。

产物：`fig_a0_discharge_vt.png`

### 阶段 A：ECM 初版

按「OCV 分箱平均 → R0 阶跃辨识 → R_dc(SOC)」三步走，在 4 颗电池上跑通。

**第一版的问题**：B0005 复测 RMSE 2.25%，没进 2% 目标线。检查发现误差集中在低 SOC 段——充放电平均法在那里仍有系统偏差，因为低 SOC 下极化不对称更明显。

### 阶段 A2：加 OCV 偏置标定（`phase_a2_ecm.py`）

用训练圈残差拟合三阶多项式 δ(SOC)，作为 OCV 的修正项。B0005 从 2.25% 压到 **1.72%**。

四颗最终结果：

| 电池 | 复测 RMSE | 说明 |
|---|---|---|
| B0006 | 0.96% | 最好 |
| B0018 | 1.49% | |
| B0005 | 1.72% | |
| B0007 | 3.29% | 前 20 圈容量再生污染 OCV，如实保留 |

**同时确认了一个边界**：NASA 是恒流放电，一次电流阶跃下极化电压只有约 40 mV，小于 OCV 估计不确定度。所以 R1/C1 的 SOC 依赖**不可单独辨识**——强行上二阶模型会让 R2 撞参数上界。选择只报可辨识的量，而不是堆参数。

产物：`fig_a2_ocv_soc.png`、`fig_a2_fit_B0005~B0018.png`、`fig_a2_r_aging.png`

### 阶段 B：统一数据层（`phase_b_build_dataset.py`）

MIT 三个 batch 共 8.27 GB，v7.3 格式（本质是 HDF5）。这一步做三件事：

1. **复刻官方 124 颗口径**（不硬编码编号，按 `LoadData.m` 的处理顺序走）
2. **重算寿命标签**，与文件自带 `cycle_life` 逐颗比对，最大偏差 **0 圈**
3. **构建曲线立方体**：124 × 100 × 300，两条（滞回 / 放电容量）

产物：`mit_cells.parquet`、`mit_cycles.parquet`（100,501 行）、`mit_dq.npz`、`mit_qd.npz`

### 阶段 C：RUL 建模（`phase_c_rul.py`）

严格按官方划分 41 / 43 / 40，只用前 100 圈，五类模型对比。

**第一轮结论**：GBM 主测试 9.05%，ElasticNet 8.72% 但 batch3 崩到 23.80%。当时的解释是「线性模型对分布漂移更敏感」。

**这个解释后来被推翻了**，见阶段 F。

产物：8 张 `fig_c_*.png`、5 个 CSV/JSON

### 阶段 D：交付物

- `交付物/数据看板.html`：自包含单文件（图 base64 内嵌），离线可开
- `交付物/项目总结报告.docx`：11 页
- `src/app/app.py`：Streamlit 四标签页小工具

### 阶段 E：仓库化

把内部过程文档归入 `docs/internal/`（已 gitignore），补 README、LICENSE、CITATION、Makefile、CI，数据路径改为环境变量可配。

### 阶段 F：ΔQ 口径修正

**触发**：与另一份独立复现（同一数据集、论文 6 特征）对比时，发现 batch3 上一个 4.9%、一个 23.80%，差近 5 倍。

**根因**：本项目的 `ΔQ(V)` 实现成了 `Q_discharge(V) − Q_charge(V)`（同一循环内充放电相减，即**滞回**），而论文定义是 `Q_100(V) − Q_10(V)`（**跨循环**、同方向）。两者量级差两个数量级，跨分布行为完全不同。

**修复**：改用数据集自带的 `Qdlin`（官方已插值），新增 `qd_from_qdlin()` / `dq_cross_cycle()`；滞回口径降级为对照特征，并加特征集消融。

**结果**：

| 配置 | 主测试 | batch3 |
|---|---|---|
| 全部 60 维 GBM | **6.20%**（R²=0.93） | 16.37% |
| 论文 6 维 GBM | 8.58% | **8.03%** |
| 论文 6 维弹性网 | 8.33% | **6.31%** |

**修正后的解释**：跨批次失效不是模型问题，是**特征里编码了充电协议**。滞回形状对快充策略敏感，batch3 换策略就整体漂移。

### 阶段 G：物理仿真（`phase_d1_pybamm_sim.py` / `phase_d2_sim_rul.py`）

**动机**：前两个阶段都是数据驱动——ECM 参数是拟合的，ΔQ 特征是统计的，中间缺一个「为什么」。
用 PyBaMM 补上：既验证降阶模型的代价，也回答 ΔQ(V) 到底在测什么。

**做了什么**

1. 三档模型（DFN / SPM / Thevenin）在同一工况下对比，并把误差拆成「结构」与「参数」两部分；
2. 7 条多步恒流快充协议，量化充电时长与温升的耦合；
3. 在 LFP 参数集上注入 LLI / LAM_pos / LAM_neg 三种退化，比对 MIT 实测的 ΔQ(V) 形态；
4. 用 SEI 与 SEI+析锂两种机制跑协议老化，与真实数据的寿命离散度对照；
5. 把仿真拆出的模式系数当特征喂回 P1，检验是否改善。

**结果**

| 项 | 结论 |
|---|---|
| 模型谱系 | SPM 相对 DFN 仅 5.2 mV；ECM 结构本身 17.2 mV；换成阶段 A 的老化参数变 201 mV —— **误差在参数不在结构** |
| 快充 | t80 从 45.2 压到 16.2 min（2.8 倍），总时长只从 85.4 降到 56.8 min（1.5 倍）；温升 8.4→29.9 K |
| ΔQ 归因 | 实测形态与 LLI（r=+0.64）、LAM_neg（r=+0.58）同向，与 LAM_pos（r=−0.07）无关 |
| 协议 vs 寿命 | 两种机制下协议都几乎无差别（离散度 0.08 / 0.05），比实测 2.61 小两个数量级 —— **没复现出来** |
| 仿真增强 | **失败**：四种组合全部持平或变差（8.33→8.41、6.31→6.69、8.58→9.63、8.03→8.31） |

**为什么增强会失败**：模式系数在 124 颗电池间几乎没有差异（LLI 占比标准差 0.018），
而仿真基与实测形态的相关只有 0.64。**物理可解释性不等于统计有效性**——这一条按验收口径
（提升 ≥5%）未达标，如实记录。

**一个反转**：初版结论曾写「同样的充电时间，快在高 SOC 段更伤（35.2% vs 39.9%）」。
这个结论在踩坑 #17 修复后**被推翻了**——那组数字来自过充到 4.68 V 的非法实验。
修好之后 `place_high` 的 3C 段一步也没走成，整条协议退化为 `base_1c`（容量衰减 3.7666% vs
3.7666%，逐位相同）。真正的结论是：**高 SOC 段的恒流快充在电压上限约束下根本执行不了**，
名义协议与实际轨迹可以完全是两件事。

### 阶段 H：P3 审计与三线合并（`phase_e_p3_audit.py` / `phase_f_bridge.py`）

**动机**：候选清单第 3 项（P3，ECM 参数辨识）由另一个 AI 独立完成。要判断它做得对不对，
需要一把能给出真值的标尺——阶段 G 的 PyBaMM 正好提供了。

**做了什么**

1. 复刻 P3 的辨识链（松弛双指数 → 先验锚定 → 幅值分解 → 反推 OCV → 仿真复算），
   然后做三组扰动：参数 ×2/×0.5/换电池（E1）、先验扫描（E2）、窗口截断 + bootstrap（E3）；
2. 把 P3 的流程套到 DFN 合成曲线上，只改采样间隔，看 R0 怎么漂（F1）；
3. 在三种退化模式下对比内阻与 ΔQ 的敏感度，回答「P1 为什么不用内阻」（F2）。

**结果**

| 项 | 结论 |
|---|---|
| 判据自证 | 参数翻倍/减半，复算 RMSE 仍 ≤ 0.31 mV；换电池才 8.7–12.0 mV → 判据无约束力 |
| 先验决定参数 | 先验 ±0.1 V ⇒ r_dc ±50 mΩ（P3 自述 ±25 mΩ，低估 4 倍）；三颗电池曲线在任何先验下重合 |
| τ2 不可辨识 | B0006 窗口 77.7 s 却报 95 s；B0005 截到 45% 时 162→94 s |
| 采样率决定 R0 | 合成曲线上 R0 从 38.6（dt=0.05 s）膨胀到 208.1 mΩ（dt=18.7 s），真值恒为 38.6 |
| 内阻 vs ΔQ | 内阻变化全在 ±7% 内且方向不一致；ΔQ 跨模式差 25 倍 → P1 选 ΔQ 是对的 |

完整推导见 [`audit.md`](audit.md)。

## 三、踩坑清单

按发现顺序排列。每条都对应一处代码或文档改动。

| # | 现象 | 根因 | 修复 |

| 1 | `TypeError: Accessing a group is done with bytes or str` | MIT 的 `cycles` 是组，不能像 `summary` 那样索引 | 先 `g[k][c,0]` 取引用，再 `f[ref][()]` 解引用 |

| 6 | 1D CNN 首版 32.87%，向均值收缩 | 41 颗上单次划分方差极大 | 改 5 折内部 CV + 早停 + 折模型集成 |

| 8 | Word 报告里图和图注被分页拆开 | 段落未设分页约束 | `keep_with_next` / `keep_together` |
| 9 | **batch3 误差 23.80%，比同类复现差 5 倍** | **ΔQ 用了滞回口径而非论文跨循环口径** | **改用 `Qdlin` + 跨循环差（阶段 F）** |

## 四、关键决策

**1. OCV 为什么用 PCHIP 而不是三次样条**
OCV 随 SOC 单调不减，普通样条会在平台区过冲出假拐点。PCHIP 保单调。

**2. 为什么只报 R0 和 R_dc，不报 R1/C1**
数据不支持（见阶段 A2）。报一个拟合好看但无物理意义的 R2 上界值，比不报更糟。

**3. 主指标为什么用中位误差**
寿命跨度 148–2237 圈，少数离群电池会让平均 APE 失去意义（EN 中位 7.77%、平均 21.27%）。

**4. 为什么选 GBM 而不是主测试最优的模型**
现在主测试最优就是 GBM（6.20%），但更关键的是它 R²=0.93。跨批次场景则应换论文 6 维配置（8.03%）。

**5. 为什么保留两种 ΔQ 口径**
滞回口径在同分布下有额外信息（60 维 GBM 6.20% < 6 维 8.58%），删掉可惜；但必须标清用途，避免混淆。`feature_sets()` 让两者可一键切换。

**6. 124 颗为什么不硬编码编号**
`LoadData.m` 的筛选顺序里有多处「按位置删除」，硬编码编号一旦数据版本变化就会错位。复刻流程比复刻结果更可靠。

## 六、复现路径

```bash
make check      # 语法 + import 自检，不需要数据
make data       # 原始 .mat → parquet / npz（需先放好 data/raw/）
make ecm        # ECM 辨识 + 老化轨迹
make rul        # RUL 建模 + 消融 + 出图（约 4 分钟）
make sim        # PyBaMM 仿真 + 与 RUL 的结合（约 1 分钟，需 pybamm）
make audit      # P3 辨识审计 + 三线桥接（约 2 分钟，需 pybamm）
make dashboard  # 生成离线 HTML 看板
```

数字核对见 [`results.md`](results.md) 第六节。
