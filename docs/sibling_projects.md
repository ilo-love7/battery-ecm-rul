# 兄弟仓库：为什么是两个，不是一个

本仓库（**锂电池 ECM-RUL**）与 **[battery-lifetime-guide](https://github.com/ilo-love7/battery-lifetime-guide)**
用的是同一批公开数据（NASA PCoE + MIT-Stanford），都在复现 Severson et al. 2019。
两者曾考虑合并，最后的决定是**保持两个独立仓库**。这份文档说明分工、口径对照，以及合并会付什么代价。

---

## 一、分工：同一个领域，两种产品形态

| | 本仓库 | battery-lifetime-guide |
|---|---|---|
| **一句话** | 把「为什么变差」和「还能跑多久」做成自洽的证据链 | 带「事故现场」的学习攻略，从零复现论文 |
| **首要读者** | 复现者 / 审稿人 / 想查结论站不站得住的人 | 想学会这套方法的学生 / 求职者 |
| **入口** | README 结果速览 → `docs/results.md` | `docs/00_怎么用这份攻略.md`（阶段 1→5） |
| **代码形态** | `src/` 库 + 10 个 `phase_*` 阶段脚本 + 合成数据测试 | 24 个 `step1..step6` 线性脚本 + `run_project.py` |
| **独有内容** | ECM（Thevenin）参数辨识；PyBaMM DFN/SPM 物理仿真；内阻真值标尺；第三方辨识审计 | NASA 34 颗标签审计；零样本迁移；域间隙拆账；KM 生存分析；删失数据利用 |
| **教育设施** | 无（不需要） | `docs/buggy_注释版/`、FAQ、面试问答卡、读者练习、宣传物料 |

**关键点：两者的独有内容是真增量，不是重复。** guide 回答「同样的早期指纹，为什么换数据集就不成立了」，
本仓库回答「ΔQ(V) 到底测的是什么物理量，以及别人辨识出的内阻能不能信」。合并不会让这些内容更多，
只会让入口变浑。

## 二、口径对照：两份复现的数字差异，来源已部分定位

同数据集、同论文六特征、同官方划分（41 训练 / 43 主测试 / 40 二级测试）：

| 模型 | 本仓库 | guide | 是否对齐 |
|---|---|---|---|
| RandomForest，主测试 43 颗 | **8.12%**（60 维特征） | **8.2%**（6 维特征） | ⚠️ 特征集不同，数值接近属巧合级证据 |
| RandomForest，paper6 口径 | 9.38% | 8.2% | ❌ 差 1.2 pp（同口径有效对照） |
| ElasticNet 六特征，主测试 | 8.33% | **5.9%** | ❌ 差 2.4 pp |
| ElasticNet 六特征，batch3 | 6.31% | 4.9% | ❌ 差 1.4 pp |

**2026-10-18 受控实验（`scripts/verify_en_l1ratio.py`）后的结论：差距主要不在超参搜索空间，在特征管线。**

- 早期归因（提交 619bbe8）认为本仓固定 `l1_ratio=0.5` 是主因。受控实验否定了这个解释的主项：
  在同一份 guide 特征快照上，固定 0.5 与 alpha × l1_ratio 网格只差 **0.14 pp**（6.18% → 6.04%），
  batch3 差 0.23 pp（5.03% → 4.80%）——收益真实但很小。
- 同一旧配置换特征来源：guide 特征快照 6.18%，本仓自己的 paper6 管线 8.33%，且误差结构完全不同
  （mean 34.8% / R² −12.9 vs mean 23.3% / R² 0.62，同样的 43 颗 cell）。
  **两条管线的 paper6 特征数值定义有差异，这是差距的主项。**
- 已核对的确定性事实：两仓主测试 43 颗**成员完全相同**（官方 test_ind 混合划分逐颗对上）；
  寿命标签仅 3 颗续跑电池差 1 圈，可忽略。

`tune_elasticnet()` 已改为同时搜 alpha 与 l1_ratio（方法论正确，保留），但**不要期待重跑后 EN 跳到 5.9%**——
预期落在 ~6.2% 一线；剩下的跨仓差距需要一次特征级 diff（电压分箱 / 插值 / 周期选取）才能定位，
该实验需要 `data/raw/mit/` 的 8.3 GB 原始数据就位。

> 结论的写法要克制：**EN 的差距已有受控实验的部分定位（超参是小项、特征管线是主项），
> 但尚未做特征级 diff。** 在特征 diff 完成前，不宣称「本仓库与 guide 的 EN 结果可以互相印证」，
> 也不宣称任何单一因素是差异的全部。

## 三、为什么不合并（三条具体代价）

1. **代码结构互斥。** guide 的价值在 `step1→step6` 的线性路径——每个脚本独立可跑、顺序即课程表。
   本仓库的价值在 `src/` 库的复用与审计。合并要么把 step 脚本改成库调用（摧毁教学路径），
   要么养两套并行代码（谁都改不动）。
2. **README 会精神分裂。** guide 的首页要同时服务四种读者（来学的 / 来复现的 / 来求职的 / 来评估的），
   本仓库的首页要在第一屏给出指标表与负结果。一个 README 塞不进两种职责。
3. **git 历史与 CI 都得重构。** 合并会丢失其中一方的提交历史；双方的测试口径也不同
   （guide 测脚本，本仓库测算法），合成一套 CI 的收益低于成本。

**该做的是交叉引用而不是合并**：本仓库的 `docs/results.md` 第 2.2 节已引用 guide 的 5.9% / 4.9%；
guide 若要引用本仓库，建议引这三条结论——ECM 内阻随采样率膨胀（采样伪影占 63%）、
PyBaMM 证实的 ΔQ(V) 机制归因（LLI + LAM_neg）、以及「能被测量 ≠ 能被辨识」这条总判断。

## 四、如果要合成一个「总入口」

不要把代码合进来，做一个轻量索引仓（或在一方加一个 `RELATED.md`）：

```
battery-lifetime-research/           # 索引仓，不放实现代码
├── README.md                        # 两仓关系图 + 口径对照 + 推荐阅读顺序
├── docs/numbers_reconciliation.md   # 上表那张「RF 一致 / EN 分歧」
└── figures/                         # 只放跨两仓的对比图
```

这样两边都能保持自己的读者路径，又不会有人在两个 8% / 5.9% 之间迷路。
